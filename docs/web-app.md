# Web 应用运行说明

面向自己或小团队的单实例应用。当前使用一个可信管理员工作空间，没有公开注册和多租户数据隔离。

## 启动与配置

根目录执行 `npm ci`，开发用 `npm run dev`，生产用 `npm run build && npm start`。开发控制台端口 5173、API 端口 3000；生产由同一个后端提供前端与 API。开发模式核心引擎在启动时编译，修改引擎后需要重启开发进程；前端支持 Vite 热更新。

部署配置放在 `.env`，不存在时 `npm run setup` 可从模板创建，已有文件不会被覆盖。

| 参数 | 默认与用途 |
| --- | --- |
| `ARENA_HOST` | `127.0.0.1`；非回环监听需要管理员密码 |
| `ARENA_PORT` | `3000`；开发代理也默认此端口 |
| `ARENA_DATA_DIR` | 仓库根 `var/`；生产设置为持久目录 |
| `ARENA_ADMIN_PASSWORD` | 本地可空；远程监听至少 12 位。用于共享管理员登录 |
| `ARENA_COOKIE_SECURE` | `false`；HTTPS 反向代理部署设为 `true` |
| `ARENA_ALLOWED_MODEL_HOSTS` | 额外可信模型网关的主机名，用逗号分隔；官方供应商已内置 |

模型、Key 和参数在页面管理。供应商连接地址必须是无凭据、查询和片段的 HTTPS URL，沿用既有 Provider 契约。自定义网关必须先加入允许列表，重定向不会转发密钥。添加模型时可获取模型列表，也可手工输入 ID；连接支持什么参数由 Provider 适配器校验，列表存在不代表参数一定可用。

“测试”会发送一次真实模型决策，页面需明确确认；“保存”不发起模型请求。启动 Bench 会运行 Probe、Stability 与正式比赛，仍会产生调用费用。

## 任务与结果

每个任务一次执行；重复启动返回同一执行。模型配置、连接版本和凭据引用在启动时固定。修改连接 Key 会保存新密文版本，活动任务继续使用原版本。复制已启动任务继承原配置快照；编辑复制后的草稿会改用当前模型配置。

调度器每次只领取一场，五模型在场内并行。任务和事件持久化到 SQLite；Worker 独立运行，定期心跳。API 不等待整场比赛结束，关闭浏览器不影响执行。进度事件只包含脱敏统计和事实标识。

取消先传播 AbortSignal，中止请求、退避和后续决策，超过 5 秒再结束 Worker。已发出的请求可能仍计费。取消或中断不生成完整比赛结果；任务状态与模型自然死亡、破产、技术 DNF 分开。

Worker 先写入事实文件，最后原子发布包含执行 ID 和文件 hash 的 `manifest.json`。服务正常停止时将活动任务标为中断；异常退出后重新启动会核对清单：完成且校验通过的执行可恢复为成功，其余标为中断，不自动再次调用模型。原有排队任务继续排队。

结果和回放通过任务 API 动态加载。查询前检查清单与 Replay hash，不读取任意客户端路径。Enrichment 失败只影响高光层。Bench 的耗时是 Provider 请求延迟累计；用量缺失有独立标记，无价格依据时不计算费用。

第一版可以导出完整结果 JSON；HTML 导出继续使用 `arena:replay`，不作为比赛成功的前提。历史样本导入只注册已有 Replay，不产生模型连接或执行费用。历史样本未导入 Run Report 时，Bench 用量显示缺失。

任务列表默认提供 Gold 1 历史演示入口，点击“观看演示”会注册只读记录并直接打开回放；重复访问使用同一记录，归档后可在“已归档”中找到。工作台复用首页与 Bench 页的米白、蓝色视觉和既有主视觉、像素城市底纹；回放样式限定在舞台区域，切换页面不会影响工作台样式。

## 数据与备份

```text
var/
  master.key                      # AES-256-GCM 密钥材料，权限 0600
  arena.sqlite                    # 模型配置、密文 Key、任务与事件
  arena.sqlite-wal / -shm          # 运行时 SQLite 文件
  server.lock                     # 单实例进程锁
  tasks/<taskId>/<executionId>/
    probe-summary.json
    stability-summary.json
    replay.json
    episode-traces.json
    run-report.json
    manifest.json
```

在停止服务后复制整个数据目录。恢复也必须使用完整目录，不能只恢复数据库而遗漏 `master.key` 或任务文件。数据库已存在但密钥文件丢失时，服务拒绝生成新密钥，防止覆盖恢复线索。

数据目录只能被一个服务实例使用；若 PID 所属服务仍存活，第二实例拒绝启动。正常关闭自动移除锁；异常退出后仅在原 PID 已不存在时回收锁。容器环境恢复备份前确认旧容器已停止，必要时移除遗留的 `server.lock`，不要在旧服务仍存活时强行解锁。

归档可恢复，不删除产物；本版没有自动清除历史记录。禁止把 `var/` 放入公开静态目录或提交到 Git。

## 部署

Node 方式：安装 Node 24.19.0+，运行 `npm ci && npm run build`，配置环境变量后用系统进程管理器运行 `npm start`。

容器方式：在 `.env` 设置至少 12 位管理员密码，执行 `docker compose up --build -d`。Compose 将应用绑定至宿主回环端口，`arena-data` 卷保存数据。若通过 HTTPS 反向代理开放访问，保留同源 Host，启用 `ARENA_COOKIE_SECURE=true`，对 `/api/tasks/*/events` 关闭响应缓冲并允许长连接。

Web 应用部署在域名根路径；当前控制台没有实现可配置的子路径前缀。已有静态导出模式仍支持独立子路径部署。

运行镜像仅复制编译后的引擎、后端、前端部署包、共享契约及回放读取所需源码和样本，不携带 node_modules、设计目录、音乐原稿或整个源码工作树。Docker 构建配置已提供；本机无 Docker 命令，容器运行仍需要在有 Docker 的环境验证。

## 当前边界

- 单管理员、单队列、单实例；多租户、并行多场、计费与权限角色未提供。
- 不支持从某一天断点续跑；失败或中断后复制为新任务。
- 不支持浏览器绕过门禁；高级 waiver 保留在 CLI，历史 waiver 仍在事实中展示。
- 动态回放与结果已接入；历史人工策略点评不复制给新比赛。
- 旧 `src/` 引擎目录与 `showcase/web/` 回放源码继续复用。workspace 和安装链已统一，旧 `web/` 仅供兼容回归，不是主应用。
- 生产前端采用 manifest 白名单，只复制实际运行图片；原稿和历史素材暂保留在 Git 来源中，没有自动清理历史或强推。
- 本轮自动化使用 Fake Provider，未执行真实付费 Bench，未部署远端服务。
